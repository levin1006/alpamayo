# Track A1 Expert Code Path Analysis

## Question

공식 Alpamayo inference path에서 하나의 PAI clip이 어떻게 CoC text와 `pred_xyz`
trajectory로 변환되는가?

## Ranked Synthesis

| Rank | Finding | Confidence | Basis |
| --- | --- | --- | --- |
| 1 | Official path is `test_inference.py` -> PAI loader -> helper message -> HF processor -> `AlpamayoR1.sample_trajectories_from_data_with_vlm_rollout`. | High | Direct script and model code |
| 2 | CoC is generated by the VLM until `<|traj_future_start|>`; trajectory is then sampled by expert + diffusion + action-space conversion, not by decoding discrete future tokens in this release path. | High | Direct model code and checkpoint config |
| 3 | `pred_xyz` is a 64-waypoint ego-frame future trajectory; official script computes a simple XY minADE against loader-provided future egomotion. | High | Loader, action space, script metric |
| 4 | Official inference ignores route, meta-action, and general VQA inputs; these are release exclusions, not missing runtime fields. | High | README release surface |
| 5 | Camera IDs and relative timestamps are returned by the loader but are not consumed by the official `test_inference.py` helper path. | Medium | Script uses flattened images only; processor module has richer path |

## End-to-End Flow

| Stage | Main artifact | Output |
| --- | --- | --- |
| 1. Select sample | `test_inference.py` | fixed `clip_id`, `t0_us` |
| 2. Load PAI clip | `load_physical_aiavdataset` | images, ego history, ego future |
| 3. Build prompt | `helper.create_message` | image messages + history placeholders + `<|cot_start|>` |
| 4. Tokenize multimodal prompt | HF processor | `tokenized_data` |
| 5. Fuse history trajectory | `TrajectoryFusionMixin.fuse_traj_tokens` | history placeholder IDs replaced with encoded history |
| 6. Generate CoC prefix | `self.vlm.generate` | tokens up to `<|traj_future_start|>` |
| 7. Sample future action | `FlowMatching.sample` + expert `step_fn` | sampled action tensor |
| 8. Convert action to trajectory | `UnicycleAccelCurvatureActionSpace.action_to_traj` | `pred_xyz`, `pred_rot` |
| 9. Report text and metric | `extract_text_tokens`, NumPy ADE | CoC text, `minADE` |

## Inference

The official path is a hybrid text-and-action pipeline:

1. PAI provides camera frames and ego-motion-derived history/future trajectories in the `t0`
   ego frame.
2. The prompt asks for CoC and future trajectory, but only the history part is represented as
   placeholder text tokens before model execution.
3. Before VLM generation, the model replaces history placeholders with encoded trajectory history
   token IDs.
4. The VLM generates CoC text until the trajectory boundary token `<|traj_future_start|>`.
5. The future trajectory is not produced by ordinary text decoding in this release inference
   path. After the boundary token, an expert/diffusion/action-space stack samples continuous
   action controls and converts them to `pred_xyz` and `pred_rot`.
6. `extra["cot"]` and `pred_xyz` are aligned by `(batch, trajectory set, trajectory sample)`.

The simplest user-review story is:

```text
4 cameras x 4 frames + 16 ego-history poses
  -> chat template with images and 48 history placeholders
  -> history placeholders replaced by encoded ego-history tokens
  -> VLM writes CoC text until <|traj_future_start|>
  -> action expert + flow matching samples acceleration/curvature
  -> unicycle action space integrates 64 future waypoints
  -> pred_xyz / pred_rot + CoC text
  -> minADE compares pred_xyz XY path to ego_future_xyz XY path
```

## Unknowns and Limits

- This report did not run live inference. It traces code and an existing local checkpoint config.
- The exact runtime text output and minADE for a new run remain nondeterministic because the
  official script samples trajectories and the README/script warn about variance.
- The official script path does not use `camera_indices`, `relative_timestamps`, or
  `absolute_timestamps` after loading. The repo processor path can use camera IDs/timestamps for
  richer preprocessing, but that is not direct evidence for the official `test_inference.py`
  execution path.
- The local checkpoint cache exposes `config.json` and weights, but not the full processor files
  in the snapshot listing inspected here. The script still builds the processor from
  `Qwen/Qwen3-VL-2B-Instruct` and injects the model tokenizer.
- `num_traj_samples=1` makes the official script's `minADE` a single-sample ADE in practice;
  the `min` becomes meaningful only when more than one trajectory sample is generated.
- This analysis should not be generalized to nuScenes/a2z yet. The release input contract is
  PAI multi-camera video plus egomotion history; external datasets still need a separate adapter
  and contract check.
